# Narrative Project Skill — NGƯỜI THỨ CHÍN

## Authority
1. Project Foundation Pillars and explicit project instructions override this skill.
2. External canon is never imported silently.
3. Distinguish proposal, selected, approved, canonical, belief, secret, uncertain, superseded, and discarded states.
4. Fiction frameworks are optional diagnostics, never mandatory templates.
5. Player agency, player verbs, environmental evidence, clue dependencies, and KCR outrank generic story structure.
6. Chapters are playable investigation units, not prose synopses.
7. KCR cannot repair contradictions. Every KCR event needs a deterministic knowledge/state trigger, manifestation, meaning, foreshadowing, and payoff.

## Workflow
Explore → Critique → Select → Canon → Timeline → Clue Graph → KCR Matrix → Playable Chapters → Red Team → Rewrite → Continuity Audit.

Selection is not approval. Rejected candidates do not leak into canon.

## Explore
Create genuinely different mystery candidates. Vary causal mechanism, thematic argument, player activity, KCR relationship, and production scope. For each: core secret, past event, missing friend discovery, protagonist connection, KCR, Vietnamese theme, twist, final reframe, strengths, weaknesses, cliché risk, gameplay potential, replay potential.

## Critique
Attack plot holes, coincidence, cliché, weak motivation, forced theme, character-as-clue-dispenser, clue unfairness, information withheld solely for surprise, passive protagonist, KCR as magic excuse, weak Vietnamese social logic, low gameplay value, mystery too easy/impossible, weak foreshadowing, and ending/theme mismatch. Findings use category, evidence, severity, root cause, affected material, repair. No single narrative-quality score.

## Canon and decisions
Record major decisions in the Decision Log. Core changes must identify old decision, new decision, rationale, and affected descendants. Never silently mutate canon.

## Timeline
Maintain canonical timeline, perceived timeline, official record, public story, and player knowledge timeline. Every divergence gets an explanation.

## Clue graph
Every important clue tracks ID, location, source, mandatory/optional, player action, observation, surface interpretation, true interpretation, dependencies, unlocks, related characters/events, foreshadowing, payoff, KCR effect, missability, and recovery path. Required progression cannot depend on one fragile missable clue.

## KCR
For every event track before state, knowledge trigger, after state, player manifestation, audio, lighting, collision/spatial change, gameplay consequence, narrative meaning, foreshadow, payoff. Escalate early/subtle → mid/unmistakable → late/structural.

## Playable chapters
Every chapter defines starting knowledge, main question, player objective, verbs, resistance, evidence, optional discoveries, KCR/state changes, revelation, reframe, unresolved question, and transition. Every scene answers: what did the player do that caused the narrative state to change?

Preferred interaction chain: approach → focus → physical interaction → sensory response → information → inference → changed state.

Avoid cutscene→walk→exposition→cutscene and interact→text-wall→done.

## Red team
Ask at least 30 adversarial questions about causality, motivation, time, locations, documents, social behavior, clue survival, knowledge, KCR timing, production feasibility, and ending payoff. Weak answers trigger revision.

## Revision and audit
Fix the highest upstream cause and regenerate only affected descendants. Audit causality, motivation, mystery fairness, twist fairness, chronology, location logic, document logic, social logic, theme, KCR, gameplay, pacing/repetition, horror, and ending payoff. Classify findings Blocking/Major/Moderate/Optional.

## Pre-production test
Before full narrative use, test the skill on three synthetic mystery premises. It must distinguish causal mechanism/theme/gameplay/KCR and detect cliché, coincidence, clue-fairness risk, and gameplay weakness. Synthetic outputs are never canon.
